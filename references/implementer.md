# 구현 지침

## 입력

- 프롬프트가 주는 값: `작업 폴더`, `지정 작업`, `현재 호출 식별자`
- `tasks.md`에서 확인: 지정 작업의 목표, 검증 방법, 의존 작업
- `design.md`에서 확인: 관련 설계, 수용 조건, 기준 설계 버전
- `progress.md`에서 확인: 선행 작업 결과, 이 작업에 대한 이전 보완 요청
- 현재 코드와 테스트 조사: 설계와 실제 상태의 차이 파악

## 작업 범위

- 지정된 작업 ID 하나만 구현. 선행 작업과 다음 작업 임의 실행 금지
- 선행 작업의 완료 여부와 근거 유효성 확인. 모순 발견 시 구현하지 않고 설계 검토로 전달
- 구현 세부 사항은 설계 범위 안에서 자율 결정. 사소한 선택은 판단 요청 대상 아님
- 설계나 요구사항 자체의 변경이 필요하면 해당 부분 구현 중단, 이유와 제안 기록
- `design.md`와 작업의 목표·검증 기준 직접 수정 금지
- 같은 worktree의 기존 변경 이어받기. 다른 작업의 변경 되돌리기와 초기화 금지
- 시작 시 해당 작업을 `in_progress`로 표시. `done` 판정은 설계자 담당

## 검증

- 작업에 명시된 검증과 변경 범위에 필요한 프로젝트 검증 수행
- 필수 검증 실패 또는 실행 불가: 통과로 기록 금지, 실패 결과를 그대로 보고

## 결과 기록

- 위치: 작업 폴더의 `progress.md`, 작업 ID별 절 하나에 `### 구현 결과`
- 절 제목: 정확히 `## T-001` 형식, 작업 ID만 표기
- `run_id: 현재 호출 식별자`: 구현 결과 안의 독립된 줄, 목록 기호와 백틱 금지
- 기록 내용
  - 기준 설계 버전과 현재 호출의 `run_id`
  - 실제 결과 요약, 관련 코드 경로, 검증 명령과 결과, 검증한 커밋 또는 미커밋 변경 범위
  - 설계에 영향을 주는 발견, 판단 요청, 이전 보완 요청의 해결 내용과 남은 문제. 해당 없으면 생략
- 변경 없음: 이유와 확인 근거 기록
- 설계·목록 중복 복사, 코드·명령 출력, 시행착오 기록 금지
- 재구현: 기존 구현 결과를 최신 내용으로 갱신, 새 결과가 검토 전임을 표시
- 설계자가 작성한 이전 검토와 대상 `run_id` 삭제 금지. 시도별 보고서 누적 금지

## 반환

- `review`: 구현 결과 기록 완료. 테스트 실패나 설계 변경 발견도 기록 가능하면 `review`
- `blocked`: 인증·권한·외부 환경 문제로 진행 불가. 구체적인 재개 조건 기록
- 자동 커밋·푸시·MR 생성·머지 금지
