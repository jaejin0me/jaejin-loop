# 로그 경로 환경 변수 지원

- 이슈: https://gitlab.example.com/tools/spec-checker/-/issues/87
- 설계 버전: v1

## 목적

- CI 작업마다 로그를 다른 경로에 남겨야 한다
- 현재 경로가 코드에 고정되어 있어 작업별 분리가 불가능하다

## 범위

- `SPEC_CHECKER_LOG` 환경 변수로 로그 파일 경로 지정
- 기존 기본 경로 동작 유지

## 제외 범위

- 로그 형식, 레벨, 회전 정책 변경
- 명령줄 옵션 추가. CI가 명령을 감싸 호출하므로 환경 변수만 사용

## 제약

- 외부 의존성 추가 금지
- 기존 호출부 시그니처 유지

## 수용 조건

- AC-1: 환경 변수 미설정 시 기존 기본 경로에 기록
- AC-2: 환경 변수 설정 시 해당 경로에 기록
- AC-3: 빈 값이나 쓸 수 없는 경로면 기본 경로로 대체하고 경고를 한 번 출력

## 설계

### 구성 요소

- `checker/logging.py`
  - `resolve_log_path()` 신규: 환경 변수를 읽어 최종 경로 반환
  - `setup_logging()` 수정: 위 함수 결과 사용

### 동작과 오류 처리

1. `SPEC_CHECKER_LOG` 읽기. 미설정이거나 공백뿐이면 기본 경로 반환
2. 지정 경로의 상위 디렉터리 쓰기 가능 여부 확인
3. 쓸 수 없으면 경고를 표준 오류로 한 번 출력하고 기본 경로 반환

### 결정 이유

- 경로 해석을 `setup_logging()`에서 분리한 이유: 환경 변수 해석만 따로 검증할 수 있다
- 경로 문제로 중단하지 않는 이유: 로그 설정 실패가 규격 확인 작업 자체를 막으면 안 된다
